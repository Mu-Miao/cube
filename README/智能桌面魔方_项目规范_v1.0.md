## 一、项目概述

智能桌面魔方是一款物联网智能家居设备管理平台，支持设备绑定、数据采集、远程控制、AI分析、语音交互等功能。

### 1.1 核心功能模块

| 模块 | 说明 |
|------|------|
| 用户认证 | 注册/登录/JWT Token |
| 设备管理 | 设备绑定/解绑/状态监控 |
| 数据采集 | 传感器数据上报与历史查询 |
| 远程控制 | 灯光/报警/音频/空调等控制 |
| AI分析 | 环境舒适度评分 + 场景化建议 |
| 日志中心 | 操作日志 + 语音日志 |
| 系统管理 | 用户管理/设备管理（管理员） |

### 1.2 技术选型

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端框架 | Vue 3 + Vite | 组合式 API (Composition API) |
| UI 组件库 | Element Plus | PC 端组件库 |
| 图表库 | ECharts | 数据可视化 |
| 状态管理 | Pinia | Vue 3 官方推荐 |
| 后端框架 | FastAPI | 异步高性能 + 自动 API 文档 |
| 数据库 | SQLite（开发）/ 可扩展 MySQL/PostgreSQL | SQLAlchemy 2.0 异步 ORM |
| 数据校验 | Pydantic v2 | 请求/响应自动校验 |
| 通信协议 | REST API + WebSocket | REST 常规操作 + WebSocket 实时推送 |
| MQTT | aiomqtt | 异步 MQTT 客户端 |
| 认证 | JWT (python-jose) | Token 认证 |
| 部署 | Docker + Gunicorn | 容器化生产部署 |

#### 3.2.3 API 封装规范

```typescript
// api/request.ts
import axios, { AxiosInstance, AxiosError } from 'axios'
import { ElMessage } from 'element-plus'
import router from '@/router'

const request: AxiosInstance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000,
})

// 请求拦截器：自动附加 Token
request.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：统一错误处理
request.interceptors.response.use(
  (response) => response.data,
  (error: AxiosError) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token')
      router.push('/login')
      ElMessage.error('登录已过期，请重新登录')
    } else {
      ElMessage.error((error.response?.data as any)?.message || '请求失败')
    }
    return Promise.reject(error)
  }
)

export default request
```

#### 3.2.4 WebSocket 封装

```typescript
// composables/useWebSocket.ts
import { ref, onUnmounted } from 'vue'

export function useWebSocket(url: string) {
  const ws = ref<WebSocket | null>(null)
  const connected = ref(false)
  const messageHandlers = new Map<string, ((data: any) => void)[]>()

  function connect() {
    ws.value = new WebSocket(`${import.meta.env.VITE_WS_BASE_URL}${url}`)

    ws.value.onopen = () => {
      connected.value = true
      // 认证
      const token = localStorage.getItem('token')
      ws.value?.send(JSON.stringify({ type: 'auth', token }))
    }

    ws.value.onmessage = (event) => {
      const msg = JSON.parse(event.data)
      const handlers = messageHandlers.get(msg.type) || []
      handlers.forEach((h) => h(msg.data))
    }

    ws.value.onclose = () => {
      connected.value = false
    }
  }

  function on(type: string, handler: (data: any) => void) {
    const handlers = messageHandlers.get(type) || []
    handlers.push(handler)
    messageHandlers.set(type, handlers)
  }

  function send(type: string, data: any) {
    ws.value?.send(JSON.stringify({ type, data }))
  }

  function disconnect() {
    ws.value?.close()
  }

  onUnmounted(disconnect)

  return { connected, connect, disconnect, on, send }
}
```

#### 4.2.3 依赖注入

```python
# api/deps.py
from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from sqlalchemy.ext.asyncio import AsyncSession
from app.db.session import get_db
from app.services.auth_service import auth_service

security = HTTPBearer()

async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
    db: AsyncSession = Depends(get_db)
):
    token = credentials.credentials
    user = await auth_service.get_user_by_token(db, token)
    if not user:
        raise HTTPException(status_code=401, detail="无效的认证凭证")
    return user

async def get_current_admin(current_user = Depends(get_current_user)):
    if current_user.role != "admin":
        raise HTTPException(status_code=403, detail="需要管理员权限")
    return current_user
```

```python
# services/ai_service.py
import httpx
from app.config import settings
from app.schemas.data import SensorDataCreate

class AIService:
    def __init__(self):
        self.api_key = settings.AI_API_KEY
        self.base_url = settings.AI_API_URL

    async def analyze_environment(self, data: SensorDataCreate) -> dict:
        async with httpx.AsyncClient() as client:
            response = await client.post(
                f"{self.base_url}/analyze",
                json=data.model_dump(),
                headers={"Authorization": f"Bearer {self.api_key}"},
                timeout=30.0
            )
            response.raise_for_status()
            return response.json()
```

## 六、通信协议规范

### 6.1 协议类型总览

本系统存在三套通信协议，分别适用于不同场景：

| 协议层 | 通信方式 | 适用方 | 说明 |
|--------|---------|--------|------|
| **硬件协议** | MQTT / HTTP | 硬件设备 ↔ 后端 | 设备握手/心跳/数据上报/控制指令 |
| **REST API** | HTTP/JSON | 前端 ↔ 后端 | 用户认证/设备管理/控制下发 |
| **WebSocket** | WS/JSON | 后端 ↔ 浏览器 | 实时数据推送/状态变更通知 |

### 6.2 硬件协议（设备 ↔ 后端）

硬件团队**必须**按以下协议与后端对接。协议支持 MQTT 和 HTTP 两种接入方式（后端内部统一处理）。

#### 6.2.1 协议类型枚举

| type 值 | 方向 | 说明 |
|---------|------|------|
| `handshake` | 设备 → 服务器 | 设备握手请求 |
| `handshake_ack` | 服务器 → 设备 | 握手响应（含 Token） |
| `heartbeat` | 设备 → 服务器 | 设备心跳包（建议 30s 一次） |
| `heartbeat_ack` | 服务器 → 设备 | 心跳响应 |
| `data_report` | 设备 → 服务器 | 传感器数据上报（建议 5s 一次） |
| `data_report_ack` | 服务器 → 设备 | 数据上报响应 |
| `control_pull` | 设备 → 服务器 | 设备主动拉取控制指令（建议 3s 一次） |
| `control_pull_ack` | 服务器 → 设备 | 控制指令响应 |
| `control_ack` | 设备 → 服务器 | 指令执行结果通知（可选） |

#### 6.2.2 完整交互流程

```
设备上电
    │
    ▼
① 发送 handshake（握手请求）
    │
    ▼
② 收到 handshake_ack（含 token）
    │
    ▼
③ 定时心跳 heartbeat（30s）
    │
    ▼
④ 定时数据上报 data_report（5s）
    │                    WebSocket → 前端浏览器（实时展示）
    ▼
⑤ 定时拉取控制指令 control_pull（3s）
    │                    ┌─ 指令执行
    │                    ▼
    └─── 执行结果 control_ack（可选）
```

#### 6.2.3 Step 1：设备握手

**设备发送握手请求**（MQTT publish 或 HTTP POST）：

```json
{
  "device_id": "AABBCCDDEEFF",
  "timestamp": 1713880000,
  "type": "handshake",
  "chip_model": "ESP32-S3",
  "version": "1.0.0"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| device_id | string | ✅ | 设备ID（建议使用 MAC 地址） |
| timestamp | int | ✅ | Unix 时间戳（秒） |
| type | string | ✅ | 固定值：`handshake` |
| chip_model | string | ✅ | 芯片型号，如 `ESP32-S3` |
| version | string | ✅ | 固件版本号 |

**服务器响应**（handshake_ack）：

```json
{
  "code": 200,
  "type": "handshake_ack",
  "msg": "握手成功",
  "timestamp": 1713880001,
  "token": "dev_abc123xyz",
  "expire_time": 86400
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 200=成功；403=失败 |
| type | string | 固定值：`handshake_ack` |
| msg | string | 返回信息 |
| timestamp | int | 服务器时间戳 |
| token | string | 临时身份凭证，**后续所有请求必须携带此 Token** |
| expire_time | int | Token 过期时间（秒），建议 24h 后重新握手 |

> **重要**：`token` 过期后设备需要重新发起 handshake 获取新 Token。


| 字段（data） | 类型 | 必填 | 说明 |
|-------------|------|------|------|
| temperature | double | ✅ | 环境温度（单位：℃） |
| humidity | double | ✅ | 环境湿度（单位：%RH） |

```json
{
  "code": 200,
  "type": "data_report_ack",
  "msg": "数据接收成功",
  "timestamp": 1713880036,
  "receive_status": true
}
```

| code | 说明 | 处理方式 |
|------|------|---------|
| 200 | 数据接收成功 | - |
| 400 | 数据格式错误 | 检查 JSON 格式和字段类型 |
| 401 | Token 无效 | 重新发起 handshake |
| 402 | 响应超时 | 重试 |
| 403 | 设备未授权 | 检查设备是否已绑定用户 |
| 500 | 服务器错误 | 联系后端开发人员 |

### 6.4 WebSocket 协议

#### 连接规范

- **URL**：`ws://{host}:8000/ws?token={jwt_token}`
- **鉴权**：连接时通过 `auth` 消息完成身份验证
- **心跳**：客户端每 30 秒发送 `ping` 消息，服务端响应 `pong`

#### 6.4.1 消息格式

所有 WebSocket 消息统一 JSON 格式：

```json
{
  "type": "message_type",
  "data": { ... },
  "timestamp": 1713880000000
}
```

#### 6.4.2 消息类型

| 方向 | type | 说明 |
|------|------|------|
| 客户端→服务端 | `auth` | 认证消息（连接时发送） |
| 客户端→服务端 | `ping` | 心跳 |
| 客户端→服务端 | `subscribe` | 订阅设备实时数据 |
| 客户端→服务端 | `unsubscribe` | 取消订阅 |
| 服务端→客户端 | `auth_result` | 认证结果 |
| 服务端→客户端 | `pong` | 心跳响应 |
| 服务端→客户端 | `sensor_data` | 传感器数据推送 |
| 服务端→客户端 | `device_status` | 设备状态变更 |
| 服务端→客户端 | `alert` | 告警通知 |
| 服务端→客户端 | `control_result` | 控制指令执行结果 |

#### 6.4.3 认证流程

```
客户端                          服务端
   │                               │
   │ ── WebSocket 连接 ──────────► │
   │                               │
   │ ── {type:"auth", token:"..."}► │
   │                               │
   │ ◄─ {type:"auth_result",       │
   │      code:0, message:"ok"}  ◄─│
```

### 6.5 MQTT 协议

#### 主题设计

```
# 设备上报数据
device/{device_id}/data

# 服务器下发控制指令
device/{device_id}/control

# 服务器下发配置更新
device/{device_id}/config

# 设备状态变更上报
device/{device_id}/status

# 服务器状态变更通知（服务器→客户端）
server/device/{device_id}/status

# AI分析结果推送
server/device/{device_id}/ai

# 告警通知
device/{device_id}/alert
server/device/{device_id}/alert

# 设备ACK确认
device/{device_id}/ack
server/device/{device_id}/ack
```

| 3004 | 设备绑定数已达上限 |

| 4002 | 数据超出有效范围 |
| 5001 | 服务器内部错误 |

| code | 说明 | 处理方式 |
|------|------|---------|
| 200 | 成功 | - |

| 401 | Token 无效 | 重新发起 handshake 获取新 Token |
| 402 | 响应超时 | 重试 |
| 403 | 设备未授权 | 检查设备是否已绑定用户 |
| 500 | 服务器错误 | 联系后端开发人员 |
